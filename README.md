# Мини-сайт заявок на мерч: опт и розница

Одностраничный сайт: каталог 438 рок-позиций (брелоки, значки, магниты, серьги), выбор режима **Опт / Розница**,
корзина-заявка, выбор способа оплаты, **автоматический счёт**, **бронь товара на 1 день** и форма «Индивидуальный дизайн».
Работает без сервера (file://) и на любом статическом хостинге (GitHub Pages).

## Как открыть
- Дважды кликните `index.html`, или
- `python3 -m http.server 8787 --directory /путь/к/merch-order-site` → http://localhost:8787

## 1. Режимы: Опт / Розница
Первый экран — две большие кнопки **«Опт»** и **«Розница»**. Выбор запоминается в браузере (localStorage);
сменить — кнопка **«Режим: … ⇄»** в шапке.

| | Опт | Розница (физлица) |
|---|---|---|
| Цены | брелок 189 ₽, магнит 180 ₽, значок 199 ₽, серьги 400 ₽/компл., значок на двух цангах +7 ₽ | **все изделия 600 ₽/шт, серьги 1 200 ₽/комплект** |
| Минимум | 500 шт суммарно (можно миксом) | от 1 шт |
| Скидки | −5% от 1000, −10% от 3000, −15% от 5000 шт | нет |

Настройки — `config.js`: `prices`, `tiers`, `minOrderQty` (опт), `retailPrices`, `retailMinOrderQty` (розница).
Наличие / «под заказ» показывается в обоих режимах.

## 3. Счёт
После отправки заявки **счёт открывается автоматически** в новой вкладке (печать / «Сохранить в PDF»), его можно скачать как HTML.
- ООО / ИП — классическая форма «Счёт на оплату» с банковским блоком, поставщиком, покупателем, суммой прописью.
- Карта — блок «Реквизиты для перевода» с назначением платежа «Оплата по счёту № …».
- Номер счёта: `ДДММГГ-NNNXX` (дата + порядковый номер в этом браузере + 2 случайных символа).
- В счёте: «Счёт действителен до 29.10.2026 включительно… товар забронирован».

Кроме счёта остаются: «Отправить письмом» (mailto на iptns@mail.ru — состав, способ оплаты, номер счёта, бронь),
скачивание JSON / CSV, а также **«Строки для вкладки „Бронь“»** (CSV, чтобы вставить в таблицу).
> Статический сайт сам письма не отправляет. Чтобы счёт уходил клиенту на почту и заявки сразу попадали в таблицу —
> подключите Apps Script (раздел 6).

## 4. Бронь на 1 день
- При выставлении счёта позиции **из наличия** бронируются до **конца следующего календарного дня** (выставлен 28.10 → бронь до 29.10 23:59). `reservationDays` в config.js.
- **К продаже = Количество на складе − активные брони.** Истёкшие и снятые брони не считаются.
- На карточке: «🔒 В наличии: 220 шт (50 забронировано до 29.10) — к продаже 170», бейдж «К продаже: 170»; если всё в брони — «Всё в брони».
- В корзине из наличия можно взять не больше «к продаже», остальное автоматически уходит в «под заказ» (изготовление от 2 до 5 недель).
- Источники броней на сайте: `reservations.js` (из вкладки «Бронь», обновляется скриптом), брони этого браузера,
  и — если задано в config.js — `reservationsCsvUrl` (опубликованный CSV вкладки «Бронь») или `appsScriptUrl`
  (онлайн-загрузка работает на http/https, например GitHub Pages).

## 5. Продажа = статус «оплачен»
Таблица учёта: **«Учёт сувенирки (копия) — внутренний»** (`1ZtqwBe0zvmxQYLmPgQ9FXOSHDOSGvEl4eNgmZrvte8Q`).
- **«Заказы»**: orderId, Дата выставления, Режим, Способ оплаты, Счёт №, Клиент, Телефон, Email, Компания, Сумма товаров, НДС/наценка, К оплате, Бронь до, **Статус**, Списано со склада, Комментарий.
- **«Бронь»**: orderId, dateIssued, expiresAt, productId, productName, category, qty, **status**, paymentMethod, customer, Строка склада, Списано.
- Статусы (выпадающий список): **бронь · оплачен · снята · истекла**.

Правила:
1. Заявка с сайта → «бронь». Склад не меняется, но «к продаже» уменьшается.
2. Менеджер ставит в «Заказы» **«оплачен»** → по строкам «Бронь» этого заказа уменьшается **«Количество»** на вкладке «Склад …»,
   строки брони → «оплачен», в «Списано со склада» ставится дата. Повторно не списывается (проверяется «Списано»).
   Списывается только забронированное количество из наличия; часть «под заказ» склад не трогает.
3. Срок брони прошёл без оплаты → «истекла», товар снова к продаже, склад не меняется.
4. «снята» — клиент отказался: бронь освобождается, склад не меняется.

Где остатки: данные складов во внутренней таблице лежат во вкладках **«Склад брелки (копия)», «Склад значки (копия)», «Склад магниты (копия)», «Склад серьги  (копия)»**
(одноимённые вкладки без «(копия)» во внутренней таблице пустые). Источник истины для «Количество» — **внутренняя копия**;
исходная «Сувенирка» (`1W9utxFz…`) после списаний синхронизируется переносом колонки «Количество» (или поменяйте вкладки в `CONF.STOCK_TABS` / `tools/common.py`, если хотите списывать прямо в «Сувенирке»).
Списывается колонка «Количество»; «Склад» и «Озон склад» не меняются — поправьте их вручную, если нужно знать, откуда ушёл товар.

## 6. Автоматизация в Google Таблице (рекомендуется) — `tools/apps-script/Code.gs`
1. Внутренняя таблица → Расширения → Apps Script → вставить `Code.gs` → выполнить `setup()` (разрешить доступ).
   Создаются триггеры: при изменении статуса в «Заказы» — списание/снятие брони; раз в час — истечение броней.
2. Развернуть → Веб-приложение (выполнять от моего имени, доступ «Все») → скопировать URL в `config.js → appsScriptUrl`.
3. Теперь каждая заявка сразу попадает в «Заказы»/«Бронь», клиенту уходит письмо со счётом (копия на iptns@mail.ru),
   а сайт показывает актуальные брони из таблицы. Меню «Мерч → Обработать заказы» — ручной прогон.

Пошаговая инструкция для первого запуска (с разрешениями и развёртыванием) — в файле **`APPS-SCRIPT-SETUP.md`**.

## 7. Скрипты на компьютере (CSV, без Apps Script)
Выгрузите вкладки в CSV в папку (zakazy.csv, bron.csv, sklad_breloki.csv, sklad_znachki.csv, sklad_magnity.csv, sklad_sergi.csv):
```bash
# заявки с сайта → строки «Заказы»/«Бронь» (+ zakazy_append.csv / bron_append.csv для вставки в таблицу)
python3 tools/sync_reservations.py push ~/Downloads/zayavka-*.json --dir /путь/к/csv
# обработать статусы: оплачен → списать склад, просроченные → истекла; обновить reservations.js и остатки сайта
python3 tools/process_orders.py /путь/к/csv [--import ~/Downloads/zayavka-*.json] [--dry-run]
# только обновить брони на сайте из bron.csv или опубликованного CSV
python3 tools/sync_reservations.py pull /путь/к/csv/bron.csv   # или URL …/pub?gid=…&output=csv
# только остатки
python3 tools/update_stock.py /путь/к/csv
```
`process_orders.py` пишет `changes-<дата>.json` — список правок (вкладка, строка, колонка, старое → новое) для переноса в Google Sheets.
Часовой пояс скриптов — Europe/Moscow (переменная `MERCH_TZ`).

## Фото товаров («отрендеренные» копии)
Сайт показывает улучшенные копии из `images/hd/<категория>/<id>.webp` (обрезка полей, апскейл, резкость, единый квадратный холст 360×360). Оригиналы лежат в `images/<категория>/` и подставляются автоматически, если hd-копии нет. После добавления новых фото запустите: `python3 tools/enhance_images.py`.
Фон блока «Хиты продаж» и стартового экрана — `images/bg/stage.jpg` (Unsplash, свободная лицензия).

## Фото фурнитуры и качества
Блок **«Фурнитура и качество»** на главной (сразу после «Хиты продаж») собирается из массива `fittingsPhotos` в `config.js`.
Сейчас в нём кадры с Ozon: кольцо и цепочка брелока с обратной стороной, крючки-рыбки серёг и живое фото покупателя.
**Фото упаковки пока нет** — в подписях и тексте блока про упаковку ничего не говорится.

Чтобы добавить снимок (в том числе упаковку, когда появится кадр):
1. Положите файл в `images/fittings/` в формате webp или jpg, желательно не тяжелее 200 КБ.
2. Добавьте запись в `fittingsPhotos`: `{ src, caption, alt }`.
3. В `caption` пишите только то, что видно на фото (например: «Упаковка», «Цанга значка»).

Секция скрывается сама, если массив пуст. Кнопка «Смотреть отзывы на Ozon» берёт ссылку из `config.js → ozon`. Клик по фото открывает увеличение.
